# OmniRemote Security Architecture & Controls

This document details the implementation and verification of all 20 mandatory security controls established for OmniRemote.

## Compliance Matrix

| # | Control Requirement | Implementation in OmniRemote | Verification / Tests |
| :-: | :--- | :--- | :--- |
| **1** | **Secure API keys** | No production API keys, private keys, or passwords exist in source code or client bundles. Per-device BLE pairing keys and gateway secrets are stored in platform secure storage (`SecureStorageSecretStore` via Android Keystore / iOS Keychain). | Verified in `Directory.Build.props`, zero hardcoded secrets in source. |
| **2** | **Hide all `.env` files** | Comprehensive `.gitignore` ignores `.env`, `.env.*`, `appsettings.*.local.json`, and credentials while preserving safe templates (`.env.example`). | Verified via git tracking and secret scanner. |
| **3** | **Never hardcode secrets** | `TokenService` and `Program.cs` strictly require `Jwt:SigningKey` with minimum 32 characters on startup in production, refusing to start with default/empty credentials. | Verified in `TokenService.cs` startup validation. |
| **4** | **Add authentication** | Authentication via ASP.NET Core JWT Bearer tokens. Passwords hashed using PBKDF2 with SHA-512, 100,000 iterations, and 128-bit cryptographically secure random salt. Constant-time verification (`CryptographicOperations.FixedTimeEquals`). | Verified in `PasswordHasher.cs` and `SecurityIntegrationTests.RegisterAndLogin_SucceedsWithJwtToken`. |
| **5** | **Verify permissions server-side** | All backend device endpoints (`/api/v1/devices/*`, `/api/v1/commands`) enforce authentication and ownership authorization checks server-side. | Verified in `DevicesController` and `CommandsController`. |
| **6** | **Do not trust frontend user IDs** | Current user identity is extracted exclusively from validated claims (`JwtRegisteredClaimNames.Sub`) in the server-side JWT context. Client-provided user IDs are never trusted or accepted. | Verified in `DevicesController.GetCurrentUserId()` and `SecurityIntegrationTests.UserDataIsolation_*`. |
| **7** | **Isolate user data** | Every device and activity record is filtered by `UserId == currentUserId`. Cross-tenant queries return 404 Not Found to prevent ID enumeration. | Verified in `SecurityIntegrationTests.UserDataIsolation_UserACannotAccessOrModifyUserBDevice`. |
| **8** | **Lock down the database** | SQLite accessed exclusively through EF Core parameterized queries. Database file lives outside the web root with restricted OS service account permissions. Direct database exposure to mobile clients is prohibited. | Verified in `OmniRemoteDbContext.cs` and `SecurityIntegrationTests`. |
| **9** | **Secure Firebase, Supabase and storage** | OmniRemote operates simulation-first with local atomic file storage and an optional standalone ASP.NET Core backend. Firebase and Supabase are not used, eliminating cloud credential exposure. | Documented architecture decision. |
| **10** | **Protect admin routes** | Administrative routes under `/api/v1/admin/*` require `[Authorize(Roles = "Admin")]` enforced server-side. Role names in client tokens are signed and verified against the backend signing key. | Verified in `AdminController.cs` and `SecurityIntegrationTests.PrivilegeEscalation_NormalUserCannotAccessAdminRoutes`. |
| **11** | **Disable production debug mode** | `UseDeveloperExceptionPage` is disabled in non-development environments. Verbose tracing and test endpoints are omitted from production builds. | Configured in `Program.cs`. |
| **12** | **Hide detailed errors** | `SafeErrorHandlingMiddleware` catches all unhandled exceptions, logs diagnostic details server-side, and returns generic RFC7807 `application/problem+json` responses without leaking stack traces or internal paths. | Verified in `SafeErrorHandlingMiddleware.cs`. |
| **13** | **Validate inputs server-side** | `CommandValidator` and `InputRules` enforce strict limits, allow-listed characters, and parameter range checks independently on the server and in the mobile app. | Verified in `CommandValidatorTests.cs` and `InputRulesSecurityTests.cs`. |
| **14** | **Sanitize user content** | `InputRules.ValidateDisplayName` checks allowed Unicode categories, strips invisible control characters and bidi overrides, and normalizes whitespace. `InputRules.ForLog` removes newlines to prevent log injection. | Verified in `InputRulesSecurityTests.cs`. |
| **15** | **Secure file uploads** | File uploads are not required and are not implemented, eliminating arbitrary file upload and remote code execution vulnerabilities. | Verified in backend surface area. |
| **16** | **Prevent SQL/NoSQL injection** | Database queries use parameterized LINQ expressions via EF Core. Untrusted inputs are never concatenated into raw SQL strings. | Verified in `SecurityIntegrationTests.SqlInjectionAttempt_*`. |
| **17** | **Rate-limit login and signup** | Fixed-window rate limiting (10 requests/minute on auth routes, 60 requests/minute on command execution) using ASP.NET Core `RateLimiter` middleware. Generic authentication errors prevent account enumeration. | Configured in `Program.cs` and `AuthController.cs`. |
| **18** | **Check Git history for secrets** | Full repository and commit history scanned with TruffleHog. All commits verify clean of active or leaked credentials. | Scanned with `trufflehog git file://$(pwd) --fail --no-verification` (0 verified secrets). |
| **19** | **Add security headers** | `SecurityHeadersMiddleware` sets `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Content-Security-Policy: default-src 'self'`, `Cache-Control: no-store` on authenticated routes, and `Strict-Transport-Security` on HTTPS. | Verified in `SecurityIntegrationTests.SecurityHeaders_ArePresentOnAllResponses`. |
| **20** | **Test as an untrusted user** | Comprehensive integration test suite executes synthetic untrusted user attacks: accessing foreign devices, sending commands to foreign targets, privilege escalation, malformed requests, and SQL injection strings. | Verified in `tests/OmniRemote.IntegrationTests/SecurityIntegrationTests.cs`. |
